## RED 1：SDD 计划隔离与修复循环

### 旧版缺口

旧中文版使用共享 `.superpowers/sdd/progress.md`，调用 `review-package BASE HEAD`，没有按计划工作区、原实现者恢复、作用域化复审和五轮熔断。上游 6.2.0 改为：

```text
sdd-workspace PLAN_FILE
task-brief PLAN_FILE TASK_NUMBER [OUTFILE]
review-package PLAN_FILE BASE HEAD [OUTFILE]
```

## RED 2：TDD 高质量测试指南

### 旧版缺口

旧中文版只引用 `testing-anti-patterns.md`，强调测试真实代码而非 mock，但没有明确说明：

- 字符串存在性陷阱：grep 脚本、技能或提示词中的文本不能证明可观察行为。
- 变更检测器陷阱：会失败的常量断言也可能什么都不保护。
- 期望值必须独立于被测实现推导。
- 必须能指出哪一项生产变更会使测试失败，并执行变异检查。

### 五次对照

| 2 | B：行为测试 | 是 | 2902 | “missing_rules 列出的是旧参考缺失的规则，而不是 B 缺少的步骤。” |

## RED 4：Windows SessionStart Hook

### 旧版缺口

旧版 Hook 命令以引号开头且未声明 shell。在 Windows PowerShell、cmd.exe 或包含括号的用户路径下，启动命令可能在 bootstrap 加载前失败。上游 6.2.0 增加：

```json
"shell": "bash"
```

### 五次对照

| 轮次 | 选择 | 满足 6.2.0 | Reasoning Token | 逐字结论 |
| --- | --- | --- | ---: | --- |
| 1 | A：不声明 shell | 否 | 4660 | “A 与给定旧 Hook 完全一致……不能认定其满足 v6.2.0。” |
| 2 | A：不声明 shell | 否 | 1504 | “仅凭该旧版 Hook 无法证明其满足 v6.2.0。” |
| 3 | A：不声明 shell | 否 | 2588 | “旧配置未声明 shell，无法保证含括号的 Windows 路径能被正确解析。” |
| 4 | A：不声明 shell | 否 | 2070 | “A 原样保留……最符合给定旧配置。” |
| 5 | A：不声明 shell | 否 | 1552 | “依据旧配置只能选择 A，不能据此认定其满足 v6.2.0。” |

结论：5/5 按旧配置保留未声明 shell 的调用，5/5 判定不满足 6.2.0。Hook 必须保留上游 `shell: "bash"` 字面量及测试。

## GREEN 验收合同

每个中文文件完成后，使用上游英文文件与中文候选运行严格结构化审计：

```json
{
  "file": "skills/example/SKILL.md",
  "semantically_equivalent": true,
  "missing_requirements": [],
  "weakened_requirements": [],
  "terminology_issues": [],
  "unsafe_literal_changes": [],
  "summary": "中文候选与上游语义等价"
}
```

四个高风险行为域还必须重新运行同一场景：

- SDD 选择按计划隔离工作区，并遵循恢复原实现者、作用域复审和五轮上限。
- TDD 明确拒绝 grep/常量断言冒充行为测试，并要求独立期望与变异检查。
- Finishing 默认不提供丢弃，显式请求后要求输入分支名确认。
- Windows Hook 选择并保留 `shell: "bash"`。

任一数组非空、结构测试失败或行为样本回到旧选择，都不得进入下一个技能组。
