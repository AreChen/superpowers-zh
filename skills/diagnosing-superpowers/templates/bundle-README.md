# Superpowers 会话诊断资料包

会话：<session-id>
运行框架：<name> <version> (<来源标签>)    Superpowers：<version> (<sha 或 "not a checkout">; <来源标签>)
脱敏级别：skeleton | evidence | full
生成时间：<ISO 时间戳>

将头部的版本字段标注为历史证据、未经验证的快照、
当前观察结果或未知。`environment.json` 为每个环境字段及其佐证
位置记录了同样的来源区分。

## 这是什么

这是一份经过脱敏处理的编程 Agent 会话记录，该会话中安装了 superpowers，
并且出了问题。它让未参与该会话的 Agent 或人员能够判断
superpowers 是否促成了问题，如果是，应当修改什么。资料包内的报告
以 `path:line` 证据说明发生了什么。按照设计，其中
不包含对 superpowers 的诊断，也不提出修复方案；这是
读者的工作。

## 文件

- `report.md` — 诊断报告（问题陈述、判定、
  环境、会话、时间线、发现、参与情况、覆盖情况说明）。
- `case.md` — 分析人员所依据的案例文件。
- `environment.json` — 环境章节的机器可读副本。
- `timeline.md` — 按轮次记录的时间线。
- `findings/<dimension>.md` — 分析人员在各个维度上的原始发现。
- `transcripts/<session-id>.md` — 每个已检查会话按轮次呈现的
  精简版本（绝不是原始 JSONL）。各级别的工具结果正文：

  | 级别 | 工具结果正文 |
  |---|---|
  | skeleton | 有意限制；替换为 `[tool result: <tool>, <bytes> bytes, exit <code>]` |
  | evidence | 保留被引用事件的内容，包括支撑发现所需的命令和结果 |
  | full | 全部保留 |
- `scrub-log.md` — 使用的每个占位符及其类别（绝不包含
  原始值）。

## 如何阅读

先阅读 `report.md` 的 §1–2，再阅读 §7（参与情况）及其引用的证据行，
然后阅读 `transcripts/` 中对应的轮次。`path:line` 引用
指向报告者机器上的原始文件；相同的行号
在精简转录记录中以 `[L<n>]` 标记的形式保留。

## 脱敏

占位符的形式为 `<EMAIL-1>`、`<PERSON-2>`、`<SECRET-3>`、`<HOST-4>`、
`<REPO-5>`、`<ORG-6>`、`<PROPRIETARY-7>`；主目录路径会被改写为 `~/…`。同一占位符
在此资料包内始终指代同一原始值。

## 制作者说明

完成后的资料包应以实际结果替换这些说明。

脱敏后，仅使用此资料包核查每项导出的重要发现：
将其引用定位到已收录的转录记录/来源标记，阅读所引用的
命令/结果或引文，并验证其支持该主张。仅确认路径和
行号存在还不够。当脱敏级别或必要的信息隐去
导致支撑证据缺失时，记录具体的局限性。

核对报告、案例、环境、发现、README 以及任何本地 issue
草稿，使其保持一致。对照最终文件更新脱敏日志的计数，不计入日志本身。
移除过时的导出说明；区分资料包准备与归档文件
交付。保留历史锚点到已收录证据的映射。

将独立隐私审计与证据的可用性分开记录：
- 隐私审计：CLEAN 或尚未解决的遗漏项。
- 证据支持：supported 或 limited，并列出受影响的发现及原因。

若检查后内容有改动，重新执行受影响的检查。展示
最终日志、文件列表和两项结果，以供现有的归档审批使用。
将已审查的文件归档，并验证交付的归档文件与这些文件一致。
在已审查的资料包之外记录归档文件的交付，而不是在获批后更改其
内容。脱敏并不构成全面的隐私认证。
